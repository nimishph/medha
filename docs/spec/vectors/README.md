# Conformance vectors

Spec: [`../trust-formula.md`](../trust-formula.md) (version in each file's `specVersion`).

| File | Contents |
|---|---|
| `components.json` | Pure-function vectors: `round6`, `wilsonLower`, `recency`, `durability`, `emaStep`. |
| `scenarios.json` | End-to-end histories with the expected trust, components, status, gates, evidence and EMA. |
| `decision-tree.json` | §11a definitions/decision-tree vectors: fold-purity, per-case evidence isolation, `decisionPolicy` rejections. |

`components.json` and `scenarios.json` are generated by `generate.py`, an independent stdlib-only
implementation written from the spec. Do not edit them by hand; edit `generate.py` and rerun it.
`generate.py --check` (also `bun run spec:check`) fails if the committed JSON is stale.

`decision-tree.json` is hand-authored, not generated: `define`/`decision` episodes are
non-evidential metadata (§11a), not part of the trust formula `generate.py` independently
re-derives, so there is no second implementation to check the kernel against here — these vectors
instead pin down the kernel's own documented, spec-stated behavior (fold-purity, per-case
isolation, the policy gate) so a regression in `foldDefinitions`/`foldDecisionTree`/
`validateEpisodeInput`'s `'decision'` case is caught the same way a trust-math regression would be.
Case ids are **not** portable literals (they depend on the caller's `random`): episodes reference a
case by a `caseRef` label, which the runner resolves to a real id (e.g. via `newDecisionCaseId`)
before folding — only the fold's *behavior* is the cross-port vector.

## Scenario format

```jsonc
{
  "name": "guarded-trusted",
  "theta0": 0.9,                 // optional, default 0.5
  "guardKind": "ci",             // optional, default "none" (unguarded)
  "kindSpec": { "thresholds": {}, "recency": {}, "evidenceWeighting": "signal-value" }, // optional
  "steps": [                     // applied in order to a fresh entity
    { "signal": "APPLY", "at": 1700000000000, "anchors": [["git", "abc"]] },  // anchors optional
    { "ok": true, "at": 1700000040000, "kind": "ci" }                          // guard report
  ],
  "now": 1700000041000,          // the read time
  "expected": {
    "trust": 1.0, "components": { "wilson": 0, "guard": 1, "recency": 1, "durability": 1, "ceiling": 1 },
    "status": "trusted",         // derived at `now` from the final state (statusFrom)
    "storedStatus": "trusted",   // the status stored by the last fold (differs after quarantine exit)
    "gates": { "trusted": true, "active": true, "drifting": false },
    "driftDelta": 0.0, "isDrifting": false,
    "evidence": { "k": 0, "n": 0, "contextRejects": 0 }, "ema": { "mu": 0 }
  }
}
```

Signal names: `APPLY`, `SKIP`, `REJECT_CONTEXT`, `REJECT_RULE`, and the host signal `ADOPTED`
(value 0.6, trial, success) — values are in `generate.py` (`SIGNALS`) and spec §9.

## Running

Each port: load the JSON, fold each scenario from a fresh entity (spec §9), read at `now`, compare
**exactly** (all numbers are `round6` outputs). The TypeScript reference runner is
`medha-core/src/__tests__/conformance.test.ts`.
